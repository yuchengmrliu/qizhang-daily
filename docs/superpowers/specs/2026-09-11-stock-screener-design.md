# 台股自動選股網站 — 設計規格

日期:2026-09-11
狀態:已與使用者確認,待實作

## 一句話

每天收盤後自動掃描全台股,用「基本面便宜 + 技術面起漲」雙重條件挑出候選股,發佈成一個手機也能開的網站。

## 目標與非目標

**目標**
- 全自動:使用者不需要執行任何指令,打開網址就看到當天結果
- 手機可用:網址在手機瀏覽器可正常瀏覽,可加入主畫面
- 零成本:只用免費公開資料與免費託管
- 雙軌篩選:基本面估值 + 技術面起漲訊號

**非目標(v1 不做)**
- 盤中即時報價(資料為每日收盤後更新)
- 下單、券商串接
- 回測績效
- 使用者帳號、自訂條件儲存到雲端
- 美股

## 架構

```
GitHub Actions (cron,每交易日 15:30 台北時間)
  │
  ├─ 1. 抓取  → 證交所 / 櫃買 OpenAPI
  ├─ 2. 計算  → 基本面指標 + 技術面指標
  ├─ 3. 篩選  → 產出候選清單
  ├─ 4. 打包  → 產生靜態資料檔(JSON)
  └─ 5. 發佈  → GitHub Pages
                  │
                  └─→ 使用者手機/電腦瀏覽器
```

**關鍵設計決定**

- 靜態網站,無後端伺服器。所有運算在 GitHub Actions 完成,前端只讀 JSON。理由:零維運、零成本、無冷啟動。
- 發佈採 GitHub Pages artifact 上傳,**不把每日資料 commit 進 git 歷史**。理由:避免 repo 隨日子膨脹。
- 歷史行情快取存放於 Actions cache / 獨立 data 分支,只做增量更新,避免每天重抓數年資料。

## 元件

| 元件 | 職責 | 技術 |
|---|---|---|
| `fetcher` | 對外抓原始資料,負責重試與禮貌性延遲 | Python + requests |
| `store` | 歷史行情/估值的本地快取,提供增量更新 | Parquet |
| `indicators` | 由原始資料算出基本面與技術面指標 | Python + pandas |
| `screener` | 套用篩選規則,輸出候選清單與通過理由 | Python |
| `builder` | 把結果寫成前端要的 JSON | Python |
| `web` | 前端頁面:清單、個股詳細、K 線圖 | 靜態 HTML/JS + lightweight-charts |
| `workflow` | 排程、執行、發佈 | GitHub Actions |

各元件彼此只透過資料檔溝通,可獨立執行與測試。

## 資料來源

全部採用證交所與櫃買中心官方公開端點,免金鑰、免費、無第三方依賴。以下皆已於 2026-09-11 實測通過。

| 用途 | 端點 | 每個交易日一次請求 | 內容 |
|---|---|---|---|
| 上市估值 | 證交所 `BWIBBU_d`(帶 date) | 66 KB / 1,080 檔 | 收盤價、本益比、股價淨值比、殖利率 |
| 上櫃估值 | 櫃買 `peQryDate`(帶 date) | 70 KB / 885 檔 | 同上 |
| 上市行情 | 證交所 `MI_INDEX?type=ALL`(帶 date) | 4.6 MB | 開高低收、成交股數、成交筆數 |
| 上櫃行情 | 櫃買 `dailyQuotes`(帶 date) | 1.6 MB | 同上 |

行情端點回傳含權證等全部證券(上市 34,641 筆中僅 1,092 筆為四碼股票),取用時以四碼代號過濾。

**兩種歷史深度**(依成本與用途分開,這是刻意的取捨):
- **估值序列:近 3 年**。資料輕(每日 136 KB),回補 3 年僅約 100 MB,支撐「本益比歷年位階」與本益比河流圖。
- **K 線 OHLCV:近 6 個月**。資料重(每日 6.2 MB),回補 120 個交易日約 750 MB 下載、壓縮後存約 10 MB。技術面指標最長只用到 60 日,6 個月已充分涵蓋。

**歷史回補**:一次性在本機執行,產出快取檔。之後每日只抓當日增量。

**快取存放**:獨立 `data` 分支,每日以 orphan commit 強制覆蓋(不累積歷史),使 repo 維持約 25 MB 不隨日子膨脹。

## 篩選規則

**流動性門檻(先過濾,不列入評分)**
- 近 20 日均量 ≥ 500 張
- 排除全額交割股、處置股
- 排除本益比為負或無資料(虧損公司)

**基本面條件(5 項)**
1. 本益比 ≤ 該股近 3 年本益比的第 40 百分位
2. 本益比 ≤ 25(絕對上限)
3. 股價淨值比 ≤ 該股近 3 年中位數
4. 殖利率 ≥ 2%
5. 近四季 EPS ≥ 一年前的近四季 EPS(獲利未衰退)

其中 EPS 由估值資料推導:近四季 EPS = 收盤價 ÷ 本益比。因此第 5 項不需額外的財報資料源。

**技術面條件(4 項)**
1. 收盤價 > 20 日均線
2. 20 日均線今日值 > 5 個交易日前(均線走揚)
3. 當日成交量 ≥ 近 5 日均量 × 1.5
4. 收盤價 ≥ 近 60 日最高價 × 0.98(突破或逼近前高)

**入選判定**
- 基本面通過 ≥ 4 項 **且** 技術面通過 ≥ 3 項 → 列入「今日精選」
- 星等 = 總通過項數對應:9 項→⭐⭐⭐⭐⭐,8→⭐⭐⭐⭐,7→⭐⭐⭐,其餘→⭐⭐
- 每檔股票都保留逐項通過/未通過結果,供前端顯示理由

規則參數集中在單一設定檔,方便日後調整而不動程式邏輯。

## 前端頁面

**分頁 1|今日精選**
- 候選股清單,每列顯示:代號、名稱、現價、本益比(含歷年位階)、技術面狀態、星等
- 展開可見基本面與技術面的逐項理由
- 檢視切換:全部條件 / 只看基本面 / 只看技術面
- 排序:星等、本益比、漲幅

**分頁 2|個股詳細**
- K 線圖:近 6 個月日線 + 20/60 日均線 + 成交量
- 本益比河流圖:近 3 年,股價對照歷年本益比區間帶
- 條件檢查表:9 項逐項打勾/打叉
- 可輸入任意股票代號查詢,不限於入選股

**手機**:響應式版面,可加入主畫面。

## 資料量與效能

- `index.json`:篩選結果 + 全市場代號/名稱/現價/本益比(供搜尋),約 150 KB
- `stocks/{代號}.json`:該股 6 個月 K 線 + 3 年估值序列,每檔約 15 KB
- 全站發佈體積約 30 MB,在 GitHub Pages 免費額度(1 GB)內
- 首頁不載入個股資料,點進個股才按需載入單一檔案

## 錯誤處理

- 任一資料來源失敗:重試 3 次(指數退避);仍失敗則**沿用前一日資料並在頁面標示「資料更新失敗,顯示 X 月 X 日資料」**,不讓網站空白
- 非交易日:workflow 偵測當日無新資料則跳過,不覆蓋既有結果
- 個股資料缺漏:該股跳過並記錄,不影響整體流程
- 前端載入不到資料:顯示明確錯誤訊息與最後更新時間

## 測試

- `indicators`:以手算好的小型固定資料驗證均線、量能、百分位計算
- `screener`:以構造的個股資料驗證每條規則的邊界(剛好通過/剛好不通過)
- `fetcher`:以錄下的 API 回應測試解析,不在測試中打外部網路
- 端到端:以單一交易日的真實資料跑完整流程,確認產出 JSON 結構正確
